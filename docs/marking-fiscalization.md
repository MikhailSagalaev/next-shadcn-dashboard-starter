# Маркировка косметики: эксплуатация Gupil

## Что реализовано

Tilda остаётся источником оплаченного заказа. Gupil сохраняет `payment.orderid` и
`payment.systranid`, сопоставляет позиции с каталогом, принимает Data Matrix при
сборке и ставит закрывающий чек полного расчёта в надёжную очередь ЮKassa.

Заказ нельзя перевести в `SHIPPED` или `DELIVERED`, пока маркировка не завершена
и закрывающий чек не зарегистрирован.

## Разделение ЮKassa платформы и магазина

`YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` сервера используются только для
оплаты подписки Gupil. Они никогда не используются для чеков покупателей.

Владелец каждого проекта самостоятельно подключает свой аккаунт в разделе
«Проект → Интеграции → ЮKassa / онлайн-касса». В базе сохраняются Shop ID и
зашифрованный Secret key именно этого проекта. Secret key не возвращается в
браузер после сохранения.

Часовой пояс кассы и НДС доставки также задаются в интеграции проекта, а не в
переменных окружения сервера.

## Технические ключи сервера

Обязательные:

```env
MARKING_ENCRYPTION_KEY=
INTEGRATION_CREDENTIALS_ENCRYPTION_KEY=
```

`MARKING_ENCRYPTION_KEY` — случайный ключ из 64 шестнадцатеричных символов. После
начала работы менять его без процедуры перешифрования нельзя.
`INTEGRATION_CREDENTIALS_ENCRYPTION_KEY` — серверный master key для шифрования
пользовательских Secret key. Это не платёжные реквизиты Gupil или магазина.
Вместо него можно использовать уже настроенный `ENCRYPTION_KEY`.

## Подготовка

1. Применить Prisma-миграции `20260721190000_add_marking_fiscal_catalog` и
   `20260721210000_add_project_yookassa_fiscal_integration`.
2. Выполнить `yarn db:generate`.
3. Настроить технические ключи шифрования сервера.
4. Владельцу проекта подключить и проверить собственную ЮKassa в интерфейсе.
5. Настроить Tilda на отправку webhook после успешной оплаты.
6. Убедиться, что webhook содержит `payment.orderid`, `payment.systranid` и
   `payment.sys=yakassa`.
7. Запустить `bonus-app` и `gupil-fiscal-worker` из `ecosystem.config.cjs`.

## Первый чек

Первый чек создаёт существующая связка Tilda + ЮKassa. Перед промышленным
запуском обязателен реальный минимальный платёж. В чеке нужно проверить признак
`ПРЕДОПЛАТА 100%`. Gupil не исправляет уже сформированный Tilda чек.

## CSV каталога

Поддерживаются запятая и точка с запятой. Минимальные колонки:

```csv
name;price;sku;externalId;gtin;markingStatus;vatCode;paymentSubject;measure;stockOnHand
Крем для лица;1250;CREAM-01;123456789;04601234567890;MARKED_REQUIRED;11;marked;piece;24
```

Возможные `markingStatus`:

- `UNKNOWN` — настройка не завершена, отгрузка блокируется;
- `MARKED_REQUIRED` — нужен Data Matrix каждой единицы;
- `LEGACY_UNMARKED_ALLOWED` — законный старый немаркированный остаток;
- `NOT_SUBJECT` — товар не подлежит маркировке.

Каждая строка — отдельная продаваемая позиция или вариант Tilda. Сопоставление
идёт сначала по `externalId`, затем по SKU. Название не является идентификатором.

## Сборка заказа

1. Открыть заказ и раздел «Сборка и маркировка».
2. Выбрать позицию.
3. Отсканировать Data Matrix. Сканер может работать как клавиатура.
4. Убедиться, что счётчик достиг заказанного количества.
5. Нажать «Сформировать полный расчёт».
6. Дождаться статуса `SETTLED`.
7. Только после этого переводить заказ в `SHIPPED`.

Полные коды хранятся зашифрованно; для защиты от повторного использования
сохраняется SHA-256 отпечаток. В обычный API и интерфейс полный код не выводится.

## Ограничения первого релиза

- Один успешный платёж ЮKassa на один заказ Tilda.
- Не более 80 фактических позиций в закрывающем чеке.
- Возвраты денег и возврат кода в оборот пока выполняются по отдельной процедуре.
- True API для документа «Дистанционная продажа» не включён: для сторонней
  доставки до его реализации применяется регламент через личный кабинет
  Честного знака.
- Разрешительный режим 2027 года требует отдельного этапа и подтверждения
  кассового провайдера.
