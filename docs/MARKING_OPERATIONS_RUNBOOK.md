# Gupil: приёмка, склад, продажа и возврат маркированного товара

## 1. Что реализовано

Контур работает по конкретным упаковкам, а не только по количеству товара:

1. входящий УПД можно создать вручную или получить из шлюза ЭДО;
2. при приёмке сканируется полный Data Matrix каждой упаковки;
3. неизвестный GTIN, дубликат или другое расхождение отправляет упаковку в
   карантин;
4. склад хранит состояние каждого Data Matrix и активную блокировку;
5. заказ резервирует и при сборке принимает только конкретные доступные
   упаковки;
6. продажа завершается одним из двух зафиксированных способов вывода из
   оборота;
7. отгрузка разрешается только после успешного чека и подтверждённого вывода из
   оборота;
8. возвратный чек можно оформлять последовательно для разных упаковок;
9. возвращённые упаковки попадают в карантин до проверки;
10. списание, возврат поставщику, возврат в оборот и перемаркировка оформляются
    отдельными документами;
11. сверка сопоставляет Gupil, ЮKassa и доступные через шлюз сведения ГИС МТ.

## 2. Что настраивает владелец проекта

### ЮKassa

В разделе `Интеграции → ЮKassa и маркировка` владелец проекта вводит:

- `shopId` своего магазина;
- секретный ключ своего магазина;
- часовую зону кассы;
- НДС доставки, если доставка платная;
- включает отправку чеков только после успешной проверки подключения.

Реквизиты проекта не связаны с оплатой подписки Gupil и не должны находиться в
общем `.env`.

### Способ вывода из оборота

Для проекта обязательно выбирается один вариант:

- **Маркированный чек ККТ** — Data Matrix передаётся в закрывающем чеке ЮKassa.
- **ГИС МТ «Дистанционная продажа»** — коды уходят в отдельный документ ГИС МТ,
  а закрывающий чек создаётся без повторной передачи тех же кодов.

Способ сохраняется в заказе. Изменение настройки проекта не переключает уже
начатый заказ на другой канал.

### ЭДО/ГИС МТ

Доступны два режима:

- **Ручной** — Gupil готовит документ, сотрудник подписывает и отправляет его во
  внешней системе, затем вводит номер принятого документа в Gupil.
- **Шлюз оператора** — Gupil ставит документ в надёжную очередь, отправляет его
  через HTTPS API, опрашивает статус и повторяет временно неудачные запросы.

Боевой автоматический режим требует реального адаптера оператора ЭДО/ГИС МТ.
Один URL без реализации перечисленных ниже операций не является интеграцией.

## 3. Контракт шлюза

Gupil отправляет `POST` на настроенный HTTPS URL с заголовками:

- `Authorization: Bearer <ключ проекта>`;
- `Idempotency-Key: <стабильный ключ операции>`;
- `Content-Type: application/json`.

Шлюз должен поддерживать:

| `kind` | Назначение |
|---|---|
| `CAPABILITIES` | проверка соединения и возможностей |
| `SYNC_INCOMING_UPD` | список входящих УПД |
| `UPD_RECEIPT` | статус/отправка документа приёмки |
| `DISTANCE_SALE` | дистанционная продажа в ГИС МТ |
| `WRITE_OFF` | отдельное списание |
| `RETURN_TO_CIRCULATION` | возврат упаковки в оборот |
| `RETURN_TO_SUPPLIER` | возврат поставщику |
| `REMARKING` | перемаркировка |
| `DOCUMENT_STATUS` | получение актуального статуса документа |
| `RECONCILIATION` | поштучная сверка кодов и статусов |

Завершёнными считаются только статусы `SUCCEEDED` и `COMPLETED`. `ACCEPTED`,
`SUBMITTED` и `PROCESSING` означают, что операция ещё не завершена.

Ответ `SYNC_INCOMING_UPD`:

```json
{
  "documents": [
    {
      "id": "external-upd-id",
      "number": "УПД-1547",
      "date": "2026-07-28",
      "status": "SIGNED",
      "supplierName": "Поставщик",
      "supplierInn": "7700000000",
      "items": [
        {
          "name": "Крем",
          "gtin": "04601234567890",
          "quantity": 3,
          "unitCost": 1500
        }
      ]
    }
  ]
}
```

## 4. Сценарий менеджера: приёмка

1. Открыть `Интеграции → ЮKassa и маркировка → Приёмки`.
2. Нажать `Получить УПД из ЭДО` или создать приёмку вручную.
3. Проверить поставщика, номер, дату, позиции, GTIN и количество.
4. Сканировать полный Data Matrix каждой физической упаковки.
5. Если появилась ошибка, открыть расхождение:
   - связать неизвестный GTIN с правильным товаром;
   - оставить в карантине для дополнительной проверки;
   - вернуть поставщику;
   - оформить списание.
6. Когда количество совпало и карантин разобран, нажать `Завершить сверку`.
7. Для ручного режима подписать УПД во внешней системе и в Gupil нажать
   `Подтвердить принятый УПД`, указав внешний номер.
8. После успешного подтверждения упаковки получают статус `Доступна`, а
   агрегированный остаток увеличивается.

Галочка сотрудника сама по себе не подтверждает переход права на товар и не
открывает склад.

## 5. Сценарий менеджера: заказ и отгрузка

1. Оплаченный заказ приходит от Tilda и создаёт уведомление.
2. Gupil резервирует доступные упаковки для маркированных позиций.
3. На странице заказа менеджер сканирует каждую фактически вложенную упаковку.
4. Gupil проверяет GTIN, принадлежность заказу, повторное использование и
   количество.
5. После комплектации нажать `Сформировать чек и завершить продажу`.
6. Далее:
   - в режиме ККТ создаётся закрывающий чек с Data Matrix;
   - в режиме ГИС МТ создаются документ дистанционной продажи и закрывающий чек
     без повторного кода.
7. Заказ остаётся заблокированным, пока оба обязательных подтверждения не
   успешны.
8. Только статус `Готов к отгрузке` разрешает менять заказ на `Отправлен` или
   `Доставлен`.

## 6. Сценарий менеджера: возврат покупателя

1. Открыть заказ с успешным чеком полного расчёта.
2. В блоке возврата выбрать весь заказ или отдельные упаковки.
3. Для частичного возврата отсканировать фактически полученные Data Matrix.
4. Указать причину и создать возвратный чек.
5. Дождаться успешного статуса ЮKassa.
6. Возвращённые упаковки автоматически переходят в карантин.
7. В разделе `Склад` открыть упаковку и выбрать результат проверки:
   - вернуть в оборот;
   - вернуть поставщику;
   - списать;
   - перемаркировать.
8. При ручном режиме подтвердить внешний документ; при шлюзе дождаться
   квитанции.
9. Следующий частичный возврат разрешён только для оставшихся проданных
   упаковок и только после завершения предыдущего.

## 7. Списания

1. Открыть `Списания`.
2. Создать документ и добавить полные Data Matrix.
3. Указать юридически корректную причину: брак, утрата, истечение срока,
   уничтожение, собственные нужды или иное основание.
4. Передать документ на подпись.
5. В ручном режиме ввести внешний номер принятого документа; в автоматическом
   режиме дождаться статуса шлюза.
6. До подтверждения упаковки имеют статус `Ожидает списания` и недоступны для
   продажи.
7. Только после успеха ГИС МТ они становятся `Списаны`, а складской остаток
   уменьшается.

## 8. Сверка

Раздел `Сверка` выполняет чтение и ничего не списывает автоматически. Он
проверяет:

- соответствие агрегированного остатка поштучному реестру;
- упаковки без связанной приёмки;
- неуспешные и зависшие документы;
- статусы чеков в ЮKassa;
- поштучные статусы ГИС МТ, если подключён шлюз.

Неполная сверка явно показывает, какой источник недоступен. Отсутствие
подключения к ГИС МТ не выдаётся за успешную полную сверку.

## 9. Безопасный тест без покупки

1. Создать отдельный проект Gupil.
2. Подключить тестовый магазин ЮKassa, не боевой.
3. Использовать тестовый проект Tilda с оплатой в этот же тестовый `shopId`.
4. Получить тестовые коды в демоконтуре ГИС МТ.
5. Без сканера скопировать полную GS1-строку тестового Data Matrix и вставить в
   поле. Один 14-значный GTIN не является кодом конкретной упаковки.
6. Пройти приёмку, заказ, чек, возврат, карантин и списание только на тестовых
   реквизитах.
7. Проверить негативные случаи:
   - случайная короткая строка;
   - повторный Data Matrix;
   - GTIN другого товара;
   - недоступный шлюз;
   - отклонённый документ;
   - попытка отгрузить заказ до подтверждения;
   - повторный возврат той же упаковки.
8. Запустить `Сверку` и убедиться, что тестовый контур возвращает согласованные
   статусы.

Нельзя отправлять выдуманные коды через боевые реквизиты ЮKassa, ОФД или ГИС
МТ.

## 10. Критерии приёмки

- упаковка не попадает в доступный склад до принятого УПД;
- карантинная упаковка не резервируется;
- один Data Matrix нельзя принять, продать, вернуть или списать дважды;
- смена схемы проекта не меняет начатый заказ;
- чек без подтверждённого выбранного канала не разрешает отгрузку;
- ошибка очереди видна менеджеру и допускает контролируемый повтор;
- возвратная упаковка не возвращается в продажу без проверки;
- списание не меняет остаток до подтверждения ГИС МТ;
- полная сверка невозможна без ответа каждого обязательного источника.
